# Security policy

The current development code is supported on a best-effort basis. Stage 01
provides local status pairing; it is not a production execution service.
There is no security response SLA.

Do not disclose vulnerabilities or credentials in public issues. Use
[GitHub private vulnerability reporting](https://github.com/Bekzhanizb/OrbiGuild/security/advisories/new)
if enabled. If unavailable, open a minimal issue asking for a private contact,
without exploit details or sensitive data. The maintainer should enable private
reporting before a public release.

Include the affected revision, platform, sanitized reproduction and expected
boundary. Do not send real tokens, workspace files or private task output.

The [security model and future requirements](docs/SECURITY.md) describe the
current health-only trust boundary and deferred execution/transport design.
