# Demonstration policy

Show real capabilities and actual provenance. Stage 01 may show real local pairing and authenticated status, as well as a
runner health response. These do not demonstrate connected agents, AI execution,
provider authorization or database activity. Public comparison codes may be shown;
secret challenges and session tokens must never appear in screenshots or recordings.

Any future fixture-driven office, event replay, mock agent or example task must
carry a persistent visible **Demo / Simulated data** label. Disclose the data
source in recordings and screenshots. Keep demo events separate from real event
provenance and prevent them from triggering tools or production actions.

Never show fabricated successful work, invented integrations, fake balances or
real credentials. Use deliberately nonfunctional test values only inside tests;
do not put fake API key fields in product screens. Do not collect real provider
keys merely to make a demonstration look functional.

Office animations are a read-only projection of validated events, not evidence of
execution by themselves. Public claims must match the implementation and the
[roadmap](ROADMAP.md).
